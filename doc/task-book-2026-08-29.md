# FlashStickNote Reliability Improvement Task Book (2026-08-29)

## Scope and Principles

- Implement on `avalonedit-editor`; preserve the user's local `conf.json` and exclude it from commits.
- Eliminate note data-loss and state-consistency risks before improving file synchronization and build reproducibility.
- Verify and commit each independently deliverable task.
- Failed saves, deletes, and synchronizations must preserve existing user data and log the cause.

## T1 Atomic Save and Delete Consistency

**Goal**: Renaming a txt or md note cannot delete its old content when creating the new file fails. A note leaves the list only after it reaches the recycle directory.

**Scope**:

- Write a temporary file in the target directory and replace the target only after the write succeeds.
- Return save and delete outcomes from storage and log failures.
- Update the collection and selection only after a successful delete.

**Acceptance**:

- Renaming a txt or md note produces the new file with the correct content and removes the old file.
- An unwritable target leaves both the original file and `StoredFileName` unchanged.
- A failed recycle operation leaves the list and selection unchanged.

## T2 Non-blocking and Recoverable File Monitoring

**Goal**: Reading an externally locked file does not block the UI. Monitoring resumes after an error or buffer overflow.

**Scope**:

- Perform watcher-triggered disk reads off the UI thread and update the model only after the read completes.
- Recreate the watcher after `FileSystemWatcher.Error`, then rescan supported note files.
- Dispose watchers and timers on exit; deferred retries must not access a disposed view model.

**Acceptance**:

- Retry waits do not occupy the UI message loop.
- A recovered watcher reconciles existing creations, changes, and deletions.
- Closing the application releases watcher resources.

## T3 Reproducible Builds

**Goal**: Main and test projects do not depend on Visual Studio's machine-local NuGet fallback directory.

**Scope**:

- Clear inherited `RestoreFallbackFolders` in repository-level MSBuild configuration.
- Verify ordinary restore, build, and the test harness without machine-specific arguments.

**Acceptance**:

- Both projects restore and build without `C:\Program Files (x86)\Microsoft Visual Studio\Shared\NuGetPackages`.
- The existing executable test harness passes.

## T4 Regression Tests and Documentation

**Goal**: The T1 and T2 reliability rules have executable regressions and are documented.

**Acceptance**:

- Tests cover successful rename, failed-save protection, recycle deletion, and watcher recovery scheduling.
- `development.md` documents persistence and monitoring constraints.
- Release build and test harness pass; no unintended tracked changes are present.
